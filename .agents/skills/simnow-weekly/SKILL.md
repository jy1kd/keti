# SimNow 周报生成

## 功能
分析本周 git 提交记录，生成口语化风格的周报，写入 `周报-YYYY年M月第N周.md`。

## 执行流程

### 第一步：收集本周提交
1. 确定本周日期范围（周一到今天，通常是周五）
2. 执行 `git log --author="Ji Yao\|jy1kd" --since="YYYY-MM-DD" --until="YYYY-MM-DD+1" --oneline --stat` 获取本周所有提交
3. 读取最近的周报文件（如 `周报-2026年7月第2周.md`），了解写作风格
4. 根据提交记录，读取相关代码文件理解技术细节

### 第二步：分析与分类
将提交按主题归类：
- 功能开发（feat）
- 问题修复（fix）
- 重构优化（refactor/perf）
- 文档/配置（docs/chore）
- 测试（test）

识别每个主题的：
- 做了什么（用大白话描述）
- 踩了什么坑（技术难点）
- 学到了什么（经验教训）

### 第三步：讨论草稿（写入前完成）
向用户展示周报草稿，格式：

```
📌 [simnow-weekly]

## 周报草稿 — YYYY年M月第N周

### 一、学习心得
[2-3 段口语化的学习感悟]

### 二、工作成果
[按天或按主题组织的工作内容]

### 三、下周计划
[基于当前进度的合理预期]

---
是否需要调整？或直接写入。
```

等待用户确认。用户可能要求：
- 调整措辞或语气
- 补充/删减某些内容
- 调整下周计划

### 第四步：写入文件
用户确认后，写入 `周报-YYYY年M月第N周.md`。

## 周报写作规范

### 风格要求（重要）
- **口语化**：像跟同事聊天一样，不要像写论文。用"踩了不少坑"而不是"遇到了若干技术挑战"
- **大白话解释技术**：用比喻和类比，让非技术同事也能看懂大概
- **有细节有故事**：不要只说"做了XX"，要说"做的时候发现XX问题，最后用XX方法解决的"
- **禁止出现**：PR编号（PR-12）、文件名（useMarketWs.ts）、函数名（batchUpdate）、commit hash
- **可以用**：技术名词（WebSocket、CTP、React）、具体数据（50ms、1000+合约）

### 格式模板

```markdown
# 周报

**姓名：** Ji Yao

**部门：** 中金所技术有限公司苏州分公司

**周期：** YYYY年M月M日 — M月M日

---

## 一、学习心得

[本周学到的东西，踩过的坑，用讲故事的口吻]

---

## 二、工作成果

[按天或按主题，描述做了什么、怎么做的、结果如何]

---

## 三、下周计划

[基于当前进度的合理预期，2-3 条]
```

### 学习心得写作要点
- 从实际开发中踩的坑出发，不要泛泛而谈
- 解释为什么这个坑值得注意，怎么解决的
- 可以提 CTP 接口的特殊行为、前端框架的注意事项、架构设计的思考
- 每周 2-3 段，每段一个主题

### 工作成果写作要点
- 按时间线（周一到周五）或按主题（前端/后端/文档）组织
- 每个成果说清楚：做了什么 → 过程中遇到什么问题 → 怎么解决的 → 最终效果
- 量化数据：合约数量、帧率、延迟、测试数量
- 不要列 commit 列表，要讲故事

### 下周计划写作要点
- 基于当前未完成的工作和 git 分支状态
- 2-3 条，具体但不琐碎
- 可以提需要注意的技术风险
