# 诊断步骤详解

## 执行步骤

1. **git log 检查** — `git log --oneline -20` 了解实际提交状态
2. **读 task2.md** — 找第一个「⏳ 待开始」且依赖满足的 PR
3. **交叉验证** — task2.md 中标记「⏳ 待开始」的 PR，git log 中是否已有对应 commit？如有则跳过
4. **检测工作范围** — 根据 PR 涉及文件自动判断：
   - 仅 `server/` → 后端工作
   - 仅 `frontend/` → 前端工作
   - 两者都有 → 前后端统一处理
5. **校验分支** — 确认当前在 main 分支或合适的修复分支
6. **输出诊断结果**

## 诊断结果格式

```
📌 [simnow-bug-fix]

📋 诊断结果

当前 PR：PR-X（标题）
当前阶段：诊断完成
Bug 描述：（一句话说明）
工作范围：后端 / 前端 / 前后端（根据涉及文件自动检测）
涉及文件：
  后端：server/xxx.py, server/yyy.py
  前端：frontend/src/xxx.tsx, frontend/src/yyy.ts
依赖检查：
  - PR-X1：✅ 已完成 / ❌ 未完成（阻塞）
  - PR-X2：✅ 已完成
工作区状态：干净 / 有未提交内容（列出）

建议分支名：fix/xxx-xxx
请确认创建分支后开始根因调查。
```

## 阻塞处理
如果依赖的 PR 未完成，输出阻塞报告：
```
⚠️ 当前 PR 被阻塞

被阻塞 PR：PR-X
阻塞原因：依赖 PR-Y（状态：⏳ 待开始）

请先完成 PR-Y，或决定是否跳过。
```

## 硬约束
- 不写代码
- 不 commit
- 等待用户确认分支后才能进入下一步
