# SimNow 简历内容生成

## 功能
分析 SimNow 项目的代码变更和提交记录，生成简历版项目介绍内容，追加写入 `项目介绍-简历版.md`。

## 执行流程

### 第一步：收集信息
1. 读取 `.ua/knowledge-graph.json`，获取项目结构和模块关系
2. 执行 `git log --author="Ji Yao\|jy1kd" --oneline -30`，获取最近提交记录
3. 读取现有的 `项目介绍-简历版.md`，了解已有内容
4. 根据提交记录，读取相关的核心代码文件，理解技术细节

### 第二步：分析与筛选
从提交记录中识别：
- 新增的功能模块
- 技术难点和解决方案
- 性能优化成果
- 架构设计亮点

### 第三步：讨论 Top3（必须在写入前完成）
向用户展示三个版本各推荐的 Top3 内容，格式：

```
📌 [simnow-resume]

## 推荐写入简历的内容（Top3）

### 角色B（前端）
1. [内容概述] — 推荐理由
2. [内容概述] — 推荐理由
3. [内容概述] — 推荐理由

### 角色A（后端）
1. [内容概述] — 推荐理由
2. [内容概述] — 推荐理由
3. [内容概述] — 推荐理由

### 综合版
1. [内容概述] — 推荐理由
2. [内容概述] — 推荐理由
3. [内容概述] — 推荐理由

是否按以上内容写入？或调整后再写。
```

等待用户确认后才进入第四步。用户可能要求：
- 调整某条内容的措辞
- 替换某条推荐
- 调整顺序
- 只写入部分版本

### 第四步：写入文件
用户确认后，按以下格式追加到 `项目介绍-简历版.md`：

```markdown
---

## 角色B（前端）— [日期] 更新

l [要点内容]

## 角色A（后端）— [日期] 更新

l [要点内容]

## 综合版 — [日期] 更新

l [要点内容]
```

写入规则：
- 追加到文件末尾，不覆盖已有内容
- 每条以 `l ` 开头（小写L + 空格）
- 每条包含：动作 + 技术栈 + 具体成果/数据
- 日期格式：YYYY-MM-DD

## 简历要点写作规范

遵循已有内容的风格：

1. **结构**：l [动作] [做了什么]，[用什么技术]，[达到什么效果]
2. **动词开头**：基于、负责、设计并实现、实现、开发、排查修复
3. **技术名词准确**：React 18、TypeScript、Vite 5、@visactor/vtable、ECharts 5、FastAPI、ctp-python
4. **量化数据**：合约数量（1000+）、帧率（60FPS）、延迟（50ms）、测试数量（160+）
5. **前端版**：侧重 UI、渲染、交互、用户体验
6. **后端版**：侧重 CTP、WebSocket、数据处理、系统稳定性
7. **综合版**：合并前后端亮点，避免重复
