# 顶部导航栏优化方案

## 1. 现状分析

### 1.1 当前顶部结构

以默认「行情」标签页为例，内容区上方自上而下依次堆叠 **5 行 chrome**：

```
┌────────────────────────────────────────────────────────────────┐
│ ① status-bar  状态栏（40px）                                   │
│   ⚙ 设置 │ 连接状态 │ ⚡FPS │ 🔌IPC │         SimNow 交易终端  │
├────────────────────────────────────────────────────────────────┤
│ ② tab-bar     标签栏（36px）                                   │
│   📊行情 │ 📈K线 │ ⭐自选 │ 📋查询 │ +                          │
├────────────────────────────────────────────────────────────────┤
│ ③ market-tabs 行情/期权切换（≈33px）                           │
│   行情 │ T型期权报价                                            │
├────────────────────────────────────────────────────────────────┤
│ ④ panel-header 行情面板标题栏（≈40px）                         │
│   行情面板 │ [搜索合约...] │ 全部合约│自选合约 │ 显示全部│搜索│收藏│
├────────────────────────────────────────────────────────────────┤
│ ⑤ 行情表列头（vtable 列头，≈28px）                             │
└────────────────────────────────────────────────────────────────┘
```

合计：行情表格开始前，chrome 占用 **≈149px** 垂直空间。

其他标签页同样存在多级堆叠：

| 标签页 | 顶部堆叠内容 |
|--------|-------------|
| 行情 | 状态栏 + 标签栏 + 行情/期权切换 + 面板标题栏 + 表列头（5 行） |
| K线 | 状态栏 + 标签栏 + 拖拽条（24px）+ K线图标题栏（4 行） |
| 报单 | 状态栏 + 标签栏 + 报单标题栏（3 行，另有弹窗形态） |
| 查询 | 状态栏 + 标签栏 + 面板标题栏（内含 7 个查询子 Tab）（3 行） |
| 自选 | 状态栏 + 标签栏 + 自选标题栏（3 行） |

### 1.2 问题清单

| # | 问题 | 说明 |
|---|------|------|
| P1 | **垂直空间浪费** | 149px chrome / 行情区域总高，压缩了行情表格可视行数（约少 4~5 行） |
| P2 | **导航概念混淆** | 全局导航（标签栏）与页内模式切换（行情/期权）、页内功能分区（全部/自选）混叠，用户分不清层级 |
| P3 | **信息冗余** | 「行情面板」「查询面板」「自选合约」标题与标签标题重复；存在两套搜索入口（内联搜索框 + 「搜索合约」弹窗按钮） |
| P4 | **视觉噪音** | 4 条水平边框线层层堆叠，横向分割线密集，界面被"切条"感强烈 |
| P5 | **调试功能占位** | ⚡FPS、🔌IPC 为开发调试功能，却与交易核心信息（连接状态）平级展示 |

## 2. 优化目标与设计原则

参考无限易、文华财经等成熟交易终端，采用 **两层导航架构**：

1. **全局栏（Global Bar）** — 全应用唯一的一行：连接状态 + 工作区标签 + 全局工具。
   > 交易终端顶部只留一行"浏览器式"结构：状态 + 页签 + 工具。
2. **页面工具栏（Contextual Toolbar）** — 每个页面内部一条上下文工具行，承载该页的**全部二级导航与操作**。

**设计原则：**

- **单一事实源**：一个功能只在一个层级出现一次（如「行情/期权」切换只留在页面工具栏，不在全局栏重复）。
- **冗余即删除**：与标签标题重复的页面标题（「行情面板」等）一律删除。
- **调试降权**：FPS / IPC 收敛进「更多」菜单，不占主行。
- **不破坏既有交互**：标签拖拽分离、浮动窗口、右键菜单、快捷键全部保留。

## 3. 推荐方案：两层导航架构

### 3.1 全局栏（Global Bar）— 合并 `status-bar` + `tab-bar`

一行替代原两行：

```
┌──────────────────────────────────────────────────────────────────────┐
│ [● MD/TD] │ 📊行情 │ 📈K线 │ ... │ ✚ │  ┆  📋查询 │ ⚙ │ ⋯ │
│  连接状态     └──────── 工作区标签（可横滚）─────────┘    全局工具区    │
└──────────────────────────────────────────────────────────────────────┘
```

| 区域 | 承载元素 | 来源 |
|------|----------|------|
| 左 | 连接状态（MD/TD 指示灯 + 文字） | 原 `status-bar` 的 ConnectionStatus |
| 中 | 工作区标签列表（原 tab-bar，支持拖拽分离 / 横滚）+ `+` 新增按钮 | 原 `tab-bar` |
| 右 | 📋 查询、⚙ 设置、`⋯` 更多（收起 ⚡FPS、🔌IPC） | 原 `status-bar` + `tab-bar` 快捷区 |

- 应用标题「SimNow 交易终端」：**移除**（Electron 由原生窗口标题栏承载；Web 下作为 `document.title` 保留）。
- `⭐自选` 快捷按钮：**取消**（自选合约唯一入口收敛到行情页工具栏「自选」，见 Phase 2 实施说明）。
- 原「⚙ 设置」从状态栏移入全局工具区。

### 3.2 页面工具栏（Contextual Toolbar）— 合并各页二级导航

每个页面保留**一条**工具栏，合并该页原有的模式切换 + 标题栏 + 操作区。

**行情页** — 合并 `market-tabs` + `panel-header`：

```
┌──────────────────────────────────────────────────────────────────────┐
│ [行情|T型期权] │ [搜索合约...      ] │ [全部|自选] │ [仅交易中] [收藏] │
└──────────────────────────────────────────────────────────────────────┘
```

- 「行情面板」标题 → **删除**（与标签标题重复）。
- 内联搜索框保留（过滤表格）；「搜索合约」弹窗按钮 → 并入搜索框右侧的「高级」图标按钮（同一入口，去掉第二个显式按钮）。
- 行情表列头保留（属于表格语义，不算导航栏）。

**K线页** — 合并 `kline-page__drag` 拖拽条 + `KLineChart` 标题栏：

- 「📈 拖动此栏可转弹窗」24px 拖拽条 → **删除**，将 `data-drag-handle` 上移到 KLineChart 标题栏（整行可拖），仅在 hover 时以 cursor 提示；仍保留 `title` 提示。
- 其余（合约代码/名称/最新价 + 周期 + 指标）保持单行，已是合理形态。

**报单页 / 查询页 / 自选页**：

- 报单页标题栏保留（需展示当前合约代码，信息不可省）；可去掉「📝 报单」文字前缀，仅保留合约代码，进一步压缩宽度。
- 查询页：删除「查询面板」标题，工具栏直接承载 7 个子 Tab（报单/成交/持仓/资金/止损单/合约/K线）+ 右侧暂停/刷新。
- 自选页：删除标题栏「⭐ 自选合约」，表格直接顶到标签栏下方（计数随行情页「自选」表格内容展示，不设独立角标）。

### 3.3 改造前后对比（行情页）

| 项目 | 改造前 | 改造后 | 收益 |
|------|--------|--------|------|
| chrome 行数 | 4 行 + 表列头 | **2 行** + 表列头 | 减半 |
| chrome 高度 | ≈149px | **≈76px**（40 + 36） | **节省 ≈73px（≈49%）** |
| 水平边框线 | 4 条 | 2 条 | 视觉更干净 |
| 行情表可视行数 | N 行 | ≈ N+4 行 | 同屏多出约 4~5 行合约 |

## 4. 备选方案

### 4.1 方案 A（保守，低风险）

仅合并**页内**二级导航（保留 status-bar / tab-bar 两行全局结构）：

- 行情页：`market-tabs` + `panel-header` → 单条工具栏（同 §3.2）。
- K线页：删除拖拽条。
- 删除所有冗余页面标题。

结果：行情页 4 行 → **3 行**（≈-36px）。改动集中在 MarketPanel 一个组件，回归面小，适合作为第一步先行落地。

### 4.2 方案 C（激进）

单行全局栏 + 无独立标签栏，把工作区标签、状态、工具全塞进一行（含「更多」抽屉承载次级功能）。适合超小屏 / 极简形态，但对多标签 + 拖拽分离场景风险高，**不推荐作为主方案**。

> **取舍建议**：推荐按 **方案 A → 方案 B（§3 推荐方案）** 分两步走，A 先行交付、B 作为最终形态。

## 6. 风险与注意事项

| 风险 | 说明 | 对策 |
|------|------|------|
| **拖拽分离** | tab-bar 的 `startDetachDrag` 与标签元素绑定，合并后需确保 drag 手势区不受工具栏新增控件干扰 | 保留 tab-bar 内部 DOM/CSS 类名，GlobalBar 仅作外层容器；`data-drag-handle` 明确划分 |
| **浮动窗口** | FLOATING_CHROME_H 依赖顶部高度常量，合并改变高度后需同步 | 查 `stores/floatingWindows.ts` 中高度常量并更新 |
| **多标签溢出** | 全局栏单行放标签 + 工具，标签多时可能挤压工具区 | tab-bar 已有 `overflow-x:auto`，工具区 `flex-shrink:0` |
| **测试回归** | 现有 469 个前端测试可能断言了旧 DOM 结构/类名 | 优先用 class 语义化保留（.tab-bar 等），逐层跑 `npm test` |
| **Electron 独立窗口** | KLinePage / OrderPage 支持独立窗口，页内工具栏需在独立窗口同样可用 | 工具栏逻辑置于页面组件内（不改动独立窗口挂载方式） |
