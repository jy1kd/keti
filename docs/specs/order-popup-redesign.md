# 报单弹窗重构方案 — 对齐「无限易五档下单」设计

> 参考：[五档下单报单窗口_前端设计方案.md](D:\ss\keti\五档下单报单窗口_前端设计方案.md%20(1).md) 、[miaoda-code 五档盘口报价组件_前端设计文档.md.md](D:\ss\keti\miaoda-code-五档盘口报价组件_前端设计文档.md.md)
> 目标对象：`frontend/src/modules/order/OrderPopup.tsx`（报单弹窗）、`OrderPage.tsx`（标签页形态，浮动模式复用弹窗布局）

---

## 1. 设计目标

把现有报单弹窗从「左五档 + 右全量表单」的双栏面板，重构为参考方案中「五档下单」式的高密度浮动窗口：

- **盘口即下单入口**：点档位直接用「当前手数 + 开平方式」报单，追求「所见价即所下价」。
- **信息密度高**：单窗约 540px 宽，账户/持仓 + 参数 + 五档盘口集中一屏。
- **两态并存**：精简态（盯盘）↔ 完整态（精细报单），一键展开/收起，状态持久化。
- **复用现有能力**：行情快照、持仓/资金、撤单、反向/锁仓接口均已存在，重点是布局重组与交互语义，尽量不动后端。

## 2. 现状盘点与差距

### 2.1 当前实现

- `OrderPopup.tsx`：740px 悬浮非模态窗，标题栏（拖拽 / 放大为标签页 / 关闭）+ `order-popup__body` 双栏：
  - 左栏 `OrderQuotePanel`（合约头 → `DepthQuote` 五档 → 行情速览 grid）
  - 右栏 `OrderForm`（方向 / 开平 / 类型 / 有效期 / 投保 五个 toggle 组 + 价格步进 + 数量步进 + 提交按钮）
- `DepthQuote.tsx`（`global.css` `.depth-quote__*`）：卖盘上 / 买盘下两块，每行 `label | 价格 | 量`；**点击语义：点卖档 = 填买入价（追击），点买档 = 填卖出价**。
- `OrderPage.tsx`：`floating` 模式直接复用 `OrderPopup.css` 的双栏类名，与弹窗视觉同源；非浮动模式为行情卡片 + `OrderForm`。

### 2.2 与参考方案的差距对照

| 参考模块 | 现有实现 | 差距 |
|---|---|---|
| ① 标题栏 `五档下单-{合约}` | 已有（📝 报单-{合约}） | 缺帮助 `?`、缺收起（缩小为精简态）按钮 |
| ② 账户/持仓/持盈栏 | **无** | 需新增 `AccountBar`；数据在 `useQueryStore`（由 QueryPanel 10s 轮询填充） |
| ③ 交易参数区（左 ~200px） | `OrderForm` 全量表单 | 需压缩为下拉 + 步进；缺合约步进、快捷手数、撤最新/撤全部、平净仓、Smart Order |
| ④ 五档盘口（右 flex） | `DepthQuote` 上下两块 | 需重写为 **买量\|价格\|卖量 三列单表** + 顶部汇总行 + 最新价分隔线 + 量能条 + 挂单量；**点价语义需改** |
| ⑤ 快速买卖按钮栏 | `OrderForm` 底部提交按钮 | 独立为 `买入N手 \| 价格 \| 卖出N手`，由 MarketDepth 内嵌 `QuickTradeBar` 提供（两态均显示） |
| ⑥ 行情统计栏（完整态） | `OrderQuotePanel` 底部 stats grid | 拆为独立条，仅完整态渲染 |
| ⑦ 底部工具条 | 无 | 新增 `∧/∨ 展开收起` + `+` |

### 2.3 数据可用性核查（方案落地基础）

| 数据 | 来源 | 状态 |
|---|---|---|
| 五档 + 今开/昨结/涨停/跌停/成交量/持仓量 | `MarketSnapshot`（WS 推送） | ✅ 全量 |
| priceTick / productClass / exchangeID / 名称 | `ContractInfo`（合约列表） | ✅ 全量 |
| 持仓（多/空/净/持盈） | `PositionRecord`（`useQueryStore.positions`） | ⚠️ 依赖 QueryPanel 轮询，弹窗需自带拉取 |
| 资金（账户号/持盈） | `AccountInfo`（`useQueryStore.account`） | ⚠️ 同上 |
| 本合约活动挂单（盘口挂单量/撤单） | `refreshOrders()` + `api.cancelOrder` | ✅ 已有，需按价格聚合 |
| 撤最新 / 撤全部 | `api.cancelOrder` / `api.cancelAllOrders` | ✅ 已有 |
| 平净仓 | `api.reversePosition` / `api.lockPosition` | ✅ 已有（OrderPanel 已接线） |

### 2.4 功能缺口（需前端扩展或后端配合）

| 项 | 现状 | 影响 |
|---|---|---|
| **GTC 有效期** | 仅 gfd/fok/fak | 需扩展 `orderMapping.ts` 的 `TIME_CONDITION_TO_CTP` + `validators`（CTP 原生支持 GTC，`'3'`，但当前 `'3'` 默认值需核对） |
| **平昨** | 仅 open/close/close_today | 需 `OFFSET_TO_CTP` 增加 `close_yesterday: '2'` + 后端透传（CTP 原生字段） |
| **自动（平今优先）** | 无 | 需后端按交易所规则在 平今/平仓 间选择；涉及上期所/其他所差异，**建议后期** |
| **持仓/资金自刷新** | 依赖 QueryPanel | 弹窗需自带轻量轮询（持仓+资金，串行执行，遵守 CTP ~1 次/秒查询限制） |
| **红绿反转** | 红涨绿跌写死 | 提供配置项，**建议后期** |

## 4. 模块详细设计

### 4.1 ① 标题栏（改造 `OrderPopup` header）

- 标题 `五档下单-{instrumentID}`，随合约动态更新。
- 右：`?`（呼出快捷键说明浮层，对齐 `useHotKeys` 现有配置）、`—`（收起为精简态，等价于折叠 ⑤⑥）、`×`（关闭，保留 ESC）。
- 保留「放大为标签页」按钮（⤢）与拖拽逻辑不变。

### 4.2 ② 账户/持仓栏（新增 `AccountBar.tsx`）

| 元素 | 数据 | 说明 |
|---|---|---|
| 账户下拉 `YYB-1829143…` | `AccountInfo.accountID` | 超长省略，hover 显示全席位号；下拉列出可用资金/持仓盈亏/动态权益 |
| `持仓 多|空(净)` | `PositionRecord` 按 `instrumentID` 过滤，`posiDirection '2'/'3'` 求和 | 净仓 = 多 - 空 |
| `持盈 +1200` | `positionProfit` | 随最新价实时刷新，盈红亏绿（对齐 `--color-up/down`） |

- **数据来源决策**：`AccountBar` 打开时触发 `useQueryStore.fetchPositions()` + `fetchAccount()`，并每 10s 自刷新（与 QueryPanel 相同的串行 + 延迟节奏，避免 CTP 查询限频）。不依赖 QueryPanel 是否挂载。
- 布局模板按钮（可选，建议后期）。
- ~~右上角 `锁仓/解锁` 开关~~：**2026-08-07 用户要求移除**（AccountBar 不再显示锁仓按钮；锁仓能力保留在报单面板 `QuickActions` 一键锁仓）。

### 4.3 ③ 交易参数区（新增 `TradeParams.tsx`，压缩现有 `OrderForm`）

左列竖向堆叠，控件一律 `12px` 紧凑样式：

| 控件 | 类型 | 说明 |
|---|---|---|
| 合约 `< IC2609 >` | 步进选择器 | 左右切相邻月份（解析合约代码 + 月份 +1/-1），上下切品种；选中同步 `setOrderForm({ instrumentID })` |
| 开平方式 `自动(平今优先)` | 下拉 | 自动 / 开 / 平 / 平今 / 平昨；**本期先实现 开/平/平今**（映射现有 combOffsetFlag），自动与平昨列入 P4 |
| 投机套保 `投机` | 下拉 | 投机 / 套保 / 套利优惠（映射现有 combHedgeFlag） |
| 有效期 `GFD` | 下拉 | GFD / FAK / FOK（本期）；GTC 列入 P4 |
| 手数 `[1]` | 数字步进框 | 上下微调、键盘输入，校验 ≥1 且 ≤ 上限（复用 `validateVolumeWithLimit`，期货 500 / 市价 60 / 期权 100） |
| 快捷手数 `1 20 50 100` | 分段按钮组 | 点击即填入手数；右键自定义预设（可选，P3） |
| `撤最新` | 描边按钮 | 撤当前合约最近一笔挂单（`refreshOrders` 取最新 + `cancelOrder`） |
| `撤全部` | 描边按钮 | 撤全部未成交报单（**全部合约**，后端 `cancel_all` 语义），二次确认 |
| `平净仓` | 主按钮（蓝） | 一键对冲净持仓（复用 `reversePosition` 逻辑，弹确认） |
| `Smart Order` | 折叠模块 | 本期映射为「止损单」入口（`StopOrderForm` 已存在），预留 TWAP/冰山扩展点 |

> `OrderForm.tsx` **保留不动**，继续服务 `OrderPage`（非浮动标签页）与 `OrderPanel` 标签页；弹窗改用新的 `TradeParams`，避免破坏既有页面。

### 4.4 ④ 五档盘口（新增 `MarketDepth.tsx`，替代弹窗内 `DepthQuote`）

对齐 [miaoda-code 五档盘口报价组件设计文档](../../miaoda-code-五档盘口报价组件_前端设计文档.md.md)，作为独立组件自包含「三列十档 + 底部改价框/买卖按钮」，是报单窗口的主操作入口。三列单表 `买量 | 价格 | 卖量` 为本次重构的核心视觉变化：

```
┌──────────┬──────────┬──────────┐
│   买入    │   价格    │   卖出    │  ← ① 表头
├──────────┼──────────┼──────────┤
│  0(0)    │7395.0 +0.6│  0(0)    │  ← ② 汇总行：委买(挂单) | 最新价 涨跌 | 委卖(挂单)
├──────────┼──────────┼──────────┤
│          │ 7396.6   │   --     │
│          │ 7396.4   │   --     │  ← ③ 卖盘 5 档（价高→低，价格列红底渐变）
│          │ 7396.2   │   --     │
│          │ 7396.0   │   --     │
│          │ 7395.8   │    1     │
├━━━━━━━━━━┿━━━━━━━━━━┿━━━━━━━━━━┤  ← ④ 最新价分隔线
│    1     │ 7395.6   │          │
│   --     │ 7395.4   │          │  ← ⑤ 买盘 5 档（价高→低，量列亮色）
│   --     │ 7395.2   │          │
│   --     │ 7395.0   │          │
│   --     │ 7394.8   │          │
├──────────┴────┬─────┴──────────┤
│  7403.4  ▲▼   │   买入2手|卖出2手 │  ← ⑥ 改价框 + 快捷买卖按钮（QuickTradeBar）
└───────────────┴────────────────┘
```

**组件树**

```
<MarketDepth>
├─ <DepthHeader/>              // 买入 | 价格 | 卖出
├─ <DepthSummaryRow/>          // 委买(挂单) | 最新价 涨跌 | 委卖(挂单)
├─ <DepthLadder>               // 十档梯形表
│   ├─ <DepthRow kind="ask" ×5/>
│   ├─ <LastPriceDivider/>
│   └─ <DepthRow kind="bid" ×5/>
└─ <QuickTradeBar>             // 改价框 + 买入N手/卖出N手
```

**单档 `DepthRow` 三列语义（列语义硬绑定，杜绝买卖混淆）**

| 列 | 内容 | 视觉 | 交互 |
|---|---|---|---|
| **买入列** | 我方买挂单量（无则 `--`） | 红系 `--color-up`，背景量能条 | 点击 → 以本档价挂**买单**；点已有挂单 → 撤该买单 |
| **价格列** | 该档委托价 | 主色等宽居中 | 点击 → **填入改价框（不直接下单）** |
| **卖出列** | 卖盘挂单量 / 我方卖挂单量 | 绿系 `--color-down`，背景量能条 | 点击 → 以本档价挂**卖单**；点已有挂单 → 撤该卖单 |

- 卖盘区（上 5 档）：买入列留空底色（红渐变示距离），卖出列显示对手盘量。
- 买盘区（下 5 档）：卖出列留空底色（绿渐变），买入列显示对手盘量。
- **量能条**：背景填充宽度 = 该档量 / 当前十档最大量，直观表达盘口深度；`--` 弱化为次级灰。
- 无真实挂单价沿用现有 tick 合成兜底（买一/卖一 ± n×tick）；`DepthQuote.tsx` 保留给 `MarketPanel` 侧栏。

**关键元素**

- **汇总行**：左 `委买总量(我方挂单数)`，右 `委卖总量(我方挂单数)`；中 最新价（高亮黄 `--accent`）+ 涨跌（涨红跌绿带箭头）。
- **最新价分隔线**：高亮渐变横线标记买/卖盘分界；最新价跳动时用 `transform` 平滑移动，不整表重排。
- **改价 + 快捷买卖栏（`QuickTradeBar`）**：价格步进框默认对手价/最新价，按 tickSize 步进、键盘可输入并做涨跌停 / 最小变动价位校验；`买入N手`（红）/ `卖出N手`（绿）文字随手数联动，点击 = 以改价框价格 + 当前手数限价报单。

**点价下单流程（已确认：每次必弹确认框）**

```
点击某档 [买入/卖出] 单元格
  → 读取 本档价格 + ③ 区当前手数/开平/投保/有效期
  → 弹确认框（方向/价格/手数/开平）→ 确认后 submitOrder
  → 乐观渲染：档位立即显示「我方挂单量」（半透明 pending 态）
  → 收到委托回报 → 转实态；失败 → 回滚 + 顶部红条提示原因
```

**撤单与防误触**

- 点击已含「我方挂单量」的档位 → 撤销该档挂单；长按/右键 → 菜单（撤该档 / 改价 / 反手，P3）。
- 买入列绝不触发卖单（列语义硬绑定）；同档连续点击节流 150ms；报单进行中该档 pending 态禁止叠加点击。
- 键盘：`↑/↓` 调改价框、`F1` 买、`F2` 卖、`Esc` 撤最新。

**性能与边界**

- 细粒度订阅 + 只 diff 变化档位（key = 价格档位稳定映射），数字变动局部闪烁高亮（300ms 淡出），避免整表 re-render。
- 价格以整数 tick 存储、展示时按 tickSize 还原，禁止浮点直接比较/运算。
- 边界：点价超涨跌停 → 拦截并标红；手数 ≤0 → 按钮置灰；报单被拒 → pending 回滚 + 红条；断线 → 组件灰化、禁用点价；无持仓时平仓/撤单置灰。

### 4.5 ⑤ 快速买卖按钮栏（由 MarketDepth 内嵌 `QuickTradeBar` 提供）

`买入2手`（红，主按钮）｜ 中间价格步进框（默认对手价/最新价，可改价即限价单）｜`卖出2手`（绿）。

- 位于五档盘口底部，精简态 / 完整态**均显示**（下单闭环的一部分，不再作为完整态独立模块）。
- 按钮文字随 ③ 手数联动：手数 = 2 → 显示「买入2手」。
- 点击 = 以改价框价格 + 当前手数限价报单，复用现有校验（数量上限、涨跌停、tick 对齐）；大额单弹确认。

### 4.6 ⑥ 行情统计栏（新增 `QuoteStatsBar.tsx`，完整态）

两列 KV：`今开 / 昨结 / 最高 / 最低 / 成交量 / 持仓量`。数据全部来自 `MarketSnapshot`，涨跌方向着色；`OrderQuotePanel` 现有 stats grid 可复用其取值逻辑。

### 4.7 ⑦ 底部工具条（新增 `FooterBar.tsx`）

- 居中 `∧/∨` 切换精简态 / 完整态（`popupStore.expanded`）。
- 右下 `+`：新增关联窗口 / 加自选（预留）。

## 5. 交互与状态

- **两态切换**：`popupStore.expanded`，持久化到 localStorage（zustand `persist`，与 `userPrefsStore` 同思路）；标题栏 `—` 与底部 `∧/∨` 等价。
- **点价二次确认（已确认）**：点价即报单（对齐参考「所见价即所下价」），但**每次点档位报单都弹确认框**（复用 `ConfirmDialog`，展示方向 / 价格 / 手数 / 开平），确认后才提交；`撤全部`、`平净仓` 同样强制确认。**不提供免确认模式**。
- **手数记忆**：切换合约保留上次手数与开平方式（现状 `setOrderForm` 合并更新已满足）。
- **防抖与乐观渲染**：同档连续点击节流 150ms；确认报单后档位立即显示「我方挂单量」半透明 pending 态，收到委托回报转实态、失败回滚并顶部红条提示原因。
- **断线兜底**：连接断开 → 顶部黄条提示、下单按钮置灰（复用现有连接状态 store）。

## 9. 已确认的决策

1. **点价语义**：按参考改——点买盘档=以该价挂买单（被动），点卖盘档=以该价挂卖单（与现有追击式相反）。
2. **点价报单**：直接报单，但**每次点档位都必须弹确认框**（展示方向/价格/手数/开平），确认后才提交；`撤全部`、`平净仓` 同样强制确认，**不提供免确认模式**。
3. **弹窗默认宽度**：540px 高密度（参数区 200px + 盘口撑满，保留自由缩放）。
4. **P4 范围**：本期只做 P1-P3 前端重构（盘口/参数区/完整态），沿用现有 gfd/fok/fak 与 开/平/平今；GTC/平昨/自动开平 留待二期。
5. **OrderForm 保留**：保留供标签页使用，弹窗新做精简 `TradeParams`。
