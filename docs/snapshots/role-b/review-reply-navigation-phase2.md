## 🔵-1 「+」新增标签按钮打开「设置」标签 — ⏸️ 保留现状

**结论**：保留现状，不修改。

**理由**：
- 此为历史行为（Phase 2 前 `App.tsx` 即 `onAddTab={() => openTab(settings)}`），非本次回归。
- 设计文档 §3.1 明确「`+` 新增按钮 → 全局栏标签区尾部」，`+` 作为「新增」入口的图标语义保留；当前 `onAddTab` 打开设置标签属既有实现约定，不属于本 PR 范畴。
- ⚙ 设置按钮与 `+` 按钮当前功能重复，属于既有状态；若未来引入「新增标签选择器」，应作为独立功能迭代，不在 Phase 2 范围。

## 🔵-2 FPS 徽标开启后不可点击关闭 — ⏸️ 保留现状

**结论**：保留纯展示，不添加点击交互。

**理由**：
- 符合「调试降权」设计原则：FPS 为开发调试功能，关闭入口收敛到 ⋯ 菜单（⚡FPS toggle）与快捷键 Ctrl+Shift+M，不再占用主行交互。
- 徽标定位为「状态展示」（类似连接指示灯），非操作入口；保持交互面最小化。

## 🔵-3 文档「自选为固定标签不可拖离」与实现不一致 — ✅ 修复（文档）

**结论**：采纳建议一（文档措辞修正），不改代码行为。

**处理**：
- 审查确认：QUICK_TABS 打开自选时 `closable: true`，自选标签可关闭、可经 pill 拖离（`handleTabPointerDown` 对非固定标签生效）。
- `navigation-redesign.md` Phase 2 实施说明改为：「自选标签 `closable:true`，拖离仍可经标签 pill 完成，移除页内 handle 无功能损失」。
- 不采纳建议二（将自选 `closable` 改为 `false`）：自选保持可关闭/可拖离是既有行为，Phase 2 仅移除页内冗余 header，不改变标签语义。
