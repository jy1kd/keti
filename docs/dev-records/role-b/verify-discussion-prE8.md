## 业务讨论

### 1. 通知管理器架构

**决策**：创建 NotificationManager 类管理通知

**原因**：
- 单一职责：通知逻辑集中在 NotificationManager
- 类型丰富：支持报单、止损、连接三种通知
- 生命周期管理：closeAll() 批量清理

**通知类型**：
- `showOrderNotification`: 报单成交/状态变化
- `showStopOrderNotification`: 止损单触发/状态变化
- `showConnectionNotification`: 连接断开/恢复

### 2. 通知声音策略

**决策**：断开时播放声音，恢复时静音

**原因**：
- 断开是异常情况，需要提醒用户
- 恢复是正常情况，无需打扰
- 通过 `silent` 参数控制

**实现**：
```typescript
silent: connected, // Only play sound for disconnection
```

### 3. 状态文本映射

**决策**：CTP 编码 → 中文映射

**原因**：
- 用户友好：显示中文而非编码
- 一致性：与其他模块的状态显示一致

**映射表**：
- 报单状态：`0` → 全部成交，`1` → 部分成交，等
- 止损单状态：`pending` → 待触发，`triggered` → 已触发，等
