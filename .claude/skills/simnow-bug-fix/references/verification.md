# 验证详解

## 流程
逐条对照 task2.md 验收标准 → 人工验证 → 记录结果

## 自验证

读取 task2.md 中当前 PR 的验收标准，逐条验证。根据工作范围决定验证方式：

- **涉及后端**：运行后端测试、验证 API
- **涉及前端**：运行前端测试、验证 UI
- **前后端都涉及**：两侧都验证

```
📋 自验证清单

PR-C1：修复 TimeCondition 枚举值错误
- [x] `python -c "from ctp_wrapper.types import TimeCondition; assert TimeCondition.GFD == '3'"` 通过
- [x] 后端 FOK 校验：`timeCondition="1" + volumeCondition="3"` → 200
- [ ] 前端 `toCtpTimeCondition('gfd')` 返回 `'3'`

遗漏/推迟项：
- ❌ 遗漏：[具体项]
- ⏸️ 推迟：[具体项] — 原因：[原因]
```

⚠️ 遗漏/推迟项必须展示给用户，**等待用户决定后才能继续**（立即实现 / 确认推迟）

## 人工验证

根据工作范围选择验证方式：

**涉及后端时**：
- 结合 Swagger 文档（http://localhost:8000/docs#/）
- 调用 API 验证返回结果

**涉及前端时**：
- 浏览器页面验证 UI 表现
- 检查控制台无报错

**前后端都涉及时**：两侧都验证

## 输出格式

```
📌 [simnow-bug-fix]

📋 验证报告

PR-X：[标题]
自验证：✅ 全部通过 / ❌ 有遗漏
人工验证：✅ 通过 / ❌ 未通过

验收标准逐条结果：
1. ✅ [验收项] — [验证方法] — 通过
2. ✅ [验收项] — [验证方法] — 通过
3. ❌ [验收项] — [验证方法] — 失败，原因：[原因]

可以进入收尾阶段。
```
