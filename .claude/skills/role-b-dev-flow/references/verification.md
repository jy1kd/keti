# 验证规则

## 自验证（TDD 开发完成后）

### 流程
1. 从 task.md 提取验收标准
2. 逐条对比验收标准与实际代码：
   - ✅ 已实现
   - ❌ 遗漏（task.md 要求了但没做）
   - ⏸️ 推迟到其他 PR
3. 遗漏/推迟项展示给用户，等待决定：
   - 立即实现 → 回到开发
   - 确认推迟 → 记录到 dev-record-b.md
4. 逐条验证，每次只讨论一项
5. 验证维度：核心功能、正常路径、异常路径、调试代码清理、范围控制、文档同步
6. 未通过 → 回到第 2 步 TDD 开发修复 → 重新自验证

### 完成后
- 更新 progress.md 状态为「开发完成，待审查」
- commit
- 提示用户切换审查窗口

---

## 人工验证（审查通过后）

### 第一步：生成验证清单
1. 从 task.md 提取验收标准
2. 根据实际代码补充 task.md 未覆盖的功能点
3. 列出推迟项
4. 输出清单，每条标记「待验证」

### 第二步：逐条验证
对每一条：
1. 创建任务：`验证 [功能名]`
2. 前端：分析相关组件代码，确认交互逻辑和预期表现
3. 输出详细验证步骤：
   ```
   ### 验证项：[功能名称]
   **前置条件：** [页面状态、操作准备]
   **验证步骤：** [页面操作] → [预期表现]
   **判断标准：** ✅ 通过 / ❌ 不通过
   ```
4. 等待用户执行并反馈
5. 标记结果：通过 → ✅ 已验证，不通过 → 分析原因 → 修复 → 重新验证该项

### ⚠️ 每验证完一条，必须立即执行：
a. 记录到 verify-discussion-prX.md（验证项、步骤、结果、问题 + 业务讨论）
b. 然后才能进入下一条

### 全部验证完成后（批量 commit）
- 将所有验证记录一次性 commit：`docs(task-xx): 人工验证记录 - PR-X`
- 避免每条验证单独 commit 产生噪声
- 如验证过程中有代码修复，修复代码单独 commit，验证记录最后批量 commit
- 更新 progress.md 状态为「人工验证通过，待收尾」
- 推迟项记录到 dev-record-b.md
- commit
