# 收尾合并规则

## 流程
1. 生成标准 PR 描述：
   ```
   ## 标题
   feat/fix/refactor(task-xx): 简述

   ## 完成内容
   - 功能点 1
   - 功能点 2

   ## 影响范围
   - 修改的模块/文件

   ## 测试结果
   - 测试用例数量、通过率

   ## 人工验证问题
   - 验证中发现的问题及处理

   ## 依赖关系
   - 依赖的 PR / 被依赖的 PR

   ## 审查结论
   - 审查轮次、结论
   ```
2. 更新文档进度：
   - docs/tasks/task.md：PR 状态 → ✅ 已完成
   - docs/tasks/task-dev-flow.md：更新阶段进度
   - progress.md：更新为「已合并」
   - dev-record-b.md：补充最终记录
3. git status，如有未提交内容，做最后一次 commit
4. 知识图谱评估（**仅展示评估结果，不执行更新**）：
   ```
   知识图谱更新评估：
   - 本 PR 是否为当前阶段最后一个 PR？[是/否]
   - 本 PR 是否涉及新增/删除模块或目录重构？[是/否]
   结论：[建议更新 / 无需更新]
   ```
   - 仅展示给用户参考，由用户决定是否手动更新图谱
   - 不自动执行图谱更新操作
5. 提示用户手动执行合并（**不要自动执行**）：
   ```
   ✅ PR 开发完成，所有内容已提交。
   请手动执行合并：
   git checkout main
   git merge feature/pr-x-xxx
   git push
   ```
